
# AI B 기능 추가 요약

## 1. AI B가 추가한 기능 목록

AI B는 이미지 필터 기능의 후속 범위를 구현하여 다음 기능을 추가했습니다.

1. **흑백 필터**: 체크박스를 선택하면 이미지가 흑백으로 표시됩니다.
2. **세피아 필터**: 체크박스를 선택하면 이미지에 세피아 톤이 적용됩니다.
3. **다운로드 반영**: 미리보기에 적용된 밝기·대비·채도·흑백·세피아 필터가 다운로드 이미지에도 동일하게 적용됩니다.
4. **경계값 처리**: 밝기·대비·채도 값이 유효한 `0~200` 범위를 벗어나지 않도록 보정합니다. 밝기 0%, 대비 0%, 채도 0%와 같은 극단값도 정상 처리됩니다.

## 2. 각 기능의 동작 방식

### 2.1 흑백 필터

`state.filters.grayscale`에 체크박스 상태를 저장합니다. 사용자가 `filterGrayscale` 체크박스를 선택하면 값이 `true`가 되고, 선택을 해제하면 `false`가 됩니다. `getFilterString()`은 이 값을 기준으로 다음 CSS Canvas 필터를 생성합니다.

```js
grayscale(100%)
```

체크하지 않은 경우에는 `grayscale(0%)`가 사용되므로 원래 색상이 유지됩니다. 그 결과 모든 픽셀의 R, G, B 채널이 같은 값으로 변환되어 흑백 이미지가 됩니다.

### 2.2 세피아 필터

`state.filters.sepia`에 세피아 체크박스 상태를 저장합니다. `filterSepia` 체크박스가 선택되면 공통 필터 문자열에 다음 항목이 추가됩니다.

```js
sepia(100%)
```

선택하지 않은 경우에는 `sepia(0%)`가 사용됩니다. 세피아 필터는 이미지의 색조를 갈색 계열로 변환하여 따뜻한 톤을 만듭니다. 일반적인 이미지에서는 평균적으로 R 채널이 G 채널보다 크고, G 채널이 B 채널보다 큰 결과가 나타납니다.

### 2.3 다운로드 반영

미리보기 렌더링에서는 이미지 draw 직전에 다음과 같이 필터를 적용합니다.

```js
ctx.filter = getFilterString();
ctx.drawImage(state.image, r.x, r.y, r.w, r.h);
ctx.filter = "none";
```

다운로드 시 사용하는 오프스크린 캔버스에서도 같은 필터 문자열을 적용합니다.

```js
octx.filter = getFilterString();
octx.drawImage(state.image, r.x, r.y, r.w, r.h);
octx.filter = "none";
```

따라서 다운로드 PNG 또는 JPEG는 미리보기와 같은 이미지 필터 결과를 포함합니다. 필터를 적용한 뒤 `filter`를 `none`으로 되돌리므로 텍스트에는 이미지 필터가 중복 적용되지 않습니다.

### 2.4 경계값 처리

`getFilterString()`에서 밝기·대비·채도 값을 숫자로 변환하고 유효성을 확인한 다음 `0~200` 사이로 제한합니다.

```js
const brightness = Number.isFinite(+f.brightness)
  ? Math.max(0, Math.min(200, +f.brightness))
  : 100;
```

대비와 채도에도 동일한 방식이 적용됩니다. 이에 따라 다음 경계값이 의도한 대로 처리됩니다.

| 필터 | 경계값 동작 |
|---|---|
| 밝기 0% | 검은색에 가까운 결과가 생성됨 |
| 대비 0% | 균일한 회색에 가까운 결과가 생성됨 |
| 채도 0% | 색상 정보가 제거되어 회색조가 됨 |
| 밝기·대비·채도 200% | 각 필터의 최대 UI 범위로 처리됨 |
| 숫자가 아닌 값 | 기본값 100%으로 대체됨 |

## 3. AI A 구현과의 연결

AI A는 다음 기반 기능을 먼저 구현했습니다.

- `filter-controls` 영역과 밝기·대비·채도 슬라이더 UI
- `state.filters.brightness`, `state.filters.contrast`, `state.filters.saturate` 상태값
- `render()`의 미리보기 이미지 필터 처리
- 각 슬라이더의 `oninput` 이벤트와 캔버스 재렌더링

AI B는 이 구조를 유지하면서 다음과 같이 확장했습니다.

1. 기존 `state.filters` 객체에 `grayscale`과 `sepia` Boolean 상태를 추가했습니다.
2. AI A가 만든 `filter-controls` 영역에 흑백·세피아 체크박스를 연결했습니다.
3. 기존 `render()`의 필터 적용 코드를 `getFilterString()` 기반으로 통합했습니다.
4. AI A의 `downloadImage()` 오프스크린 캔버스에도 동일한 필터 문자열을 적용했습니다.
5. 이미지에만 필터를 적용하고 텍스트에는 영향을 주지 않도록 이미지 draw 직후 컨텍스트 필터를 `none`으로 초기화했습니다.

이 구조로 기존 밝기·대비·채도 기능은 그대로 유지되며, AI B가 추가한 흑백·세피아 기능과 여러 필터의 조합도 동일한 렌더링 경로를 통해 동작합니다.

## 4. 검사 F06~F10 실행 결과

고정 검사 10개의 AI B 담당 범위인 F06~F10을 실행했으며, 모든 검사를 통과했습니다.

| 검사 ID | 입력 | 기대값 | 결과 |
|---|---|---|---|
| `T05-F06` | 흑백 체크 | 모든 픽셀에서 R=G=B | ✅ 통과 |
| `T05-F07` | 세피아 체크 | 평균 R > 평균 G > 평균 B | ✅ 통과 |
| `T05-F08` | 밝기 150% + 흑백 + 다운로드 | 다운로드 PNG 픽셀 = 캔버스 픽셀 | ✅ 통과 |
| `T05-F09` | 밝기 0% + 다운로드 | 다운로드 PNG 평균 픽셀값 ≈ 0 | ✅ 통과 |
| `T05-F10` | 채도 200% + 세피아 + 다운로드 | 다운로드 PNG에 두 필터 모두 반영 | ✅ 통과 |

F08~F10에서 확인한 것처럼 오프스크린 캔버스에도 미리보기와 동일한 필터 문자열이 적용되므로 다운로드 결과에 필터가 누락되지 않습니다.

## 5. 수정한 파일과 주요 변경 위치

### `index.html`

- `filter-controls` 영역에 흑백 체크박스 추가
  - `id="filterGrayscale"`
- `filter-controls` 영역에 세피아 체크박스 추가
  - `id="filterSepia"`
- 추가된 UI 부분에 `<!-- [FILTER] ... -->` 주석 표시

### `styles.css`

- 필터 체크박스 레이아웃과 강조 색상 추가
  - `.filter-controls .filter-check`
  - `.filter-controls .filter-check input[type=checkbox]`
- 추가된 스타일에 `/* [FILTER] ... */` 주석 표시

### `app.js`

- `state.filters`에 `grayscale`, `sepia` 상태 추가
- `getFilterString()` 함수 추가
  - 밝기·대비·채도 값 검증 및 `0~200` 범위 제한
  - 흑백·세피아 필터 문자열 생성
- `render()`에서 공통 필터 문자열 사용
- `downloadImage()`의 오프스크린 캔버스에 동일한 필터 적용
- 미리보기와 다운로드의 이미지 draw 이후 `filter = "none"` 리셋
- 흑백·세피아 체크박스의 `onchange` 이벤트 바인딩
- 모든 변경 부분에 `// [FILTER]` 주석 표시
